# RAG 技術應用分析

本專案的核心功能之一是整合了 **RAG (Retrieval-Augmented Generation)** 技術，主要應用於**「教材練習」**相關的問答系統，而非「自訂單字卡」功能。

- **教材練習 (RAG 問答系統)**:
  此功能體現在 `qa_system.py` 中，它讓使用者可以上傳自己的教材（如 PDF、CSV 檔案），並針對教材內容進行提問。系統會從上傳的檔案中檢索最相關的資訊，然後結合大型語言模型（LLM）生成精準的回答。這就是 RAG 技術的直接應用。

- **自訂單字卡 (RAG 輔助生成)**:
  此功能利用 RAG 技術來提升單字提取的精準度。當使用者上傳文件或貼上文字時，後端會執行以下 RAG 流程：
  1.  **動態索引**: 為使用者提供的內容即時建立一個暫時的向量資料庫。
  2.  **智慧檢索**: 系統會主動在該資料庫中檢索最核心、最相關的文字段落。
  3.  **增強生成**: 最後，將檢索到的核心段落提交給大型語言模型（LLM），並指示其從這些精華內容中提取出最有價值的15個單字。這種方法比分析全文更能抓到重點，提取的單字也更具代表性。

## 使用套件與技術

- **`Langchain`**: 作為核心框架，用於建構整個 RAG 的處理流程（Chain），串連起資料讀取、向量化、檢索和生成等步驟。
- **`ChromaDB`**: 作為向量資料庫，負責儲存從教材文件轉換而來的向量（Embeddings），並提供高效的相似度搜尋功能，以快速找到與使用者問題最相關的內容。

## 技術難度

本專案的 RAG 實作技術難度屬於**中高**，原因如下：
1.  **架構整合**: 需要整合多個獨立元件，包含文件載入器 (`utils.py`)、向量資料庫建構腳本 (`build_vector_db.py`)、`ChromaDB` 服務以及 `Langchain` 的檢索鏈。
2.  **自訂流程**: `README.md` 中提到「Langchain 自訂檢索鏈」，這代表開發者不僅使用了現成模組，還根據業務需求客製化了檢索邏輯，技術要求較高。
3.  **效能調優**: 文件中提到「RAG 反應時間需優化」，這表明開發過程涉及對檢索效率、模型反應速度等複雜環節的調整與優化。

## 資料庫處理流程

RAG 的資料庫處理流程可以分為「建立」和「查詢」兩個階段：

1.  **建立階段 (Indexing)**:
    - **讀取與分割**: 使用 `build_vector_db.py` 腳本，透過 `Langchain` 的文件載入器（Document Loaders）讀取來源文件（如 `國小英文教材/` 中的 PDF、CSV）。
    - **向量化**: 將分割後的文字區塊（Chunks）透過模型轉換成高維度的數字向量（Embeddings）。
    - **儲存**: 將這些向量連同其原始文本儲存到 `ChromaDB` 向量資料庫中（位於 `chroma_db/` 或 `vector_db/` 目錄）。

2.  **查詢階段 (Querying)**:
    - **使用者提問**: 使用者在「教材練習」相關功能中提出問題。
    - **查詢向量化**: 系統將使用者的問題同樣轉換成一個向量。
    - **相似度搜尋**: 在 `ChromaDB` 中進行相似度搜尋，找出與問題向量最接近的幾個文字區塊向量。
    - **增強生成**: 將檢索到的原文文字區塊作為上下文（Context），連同使用者的原始問題一起發送給大型語言模型（Gemini）。
    - **生成答案**: 模型根據豐富的上下文生成最終的、更精確的回答，並如 `README.md` 所述，可引述資料來源。
