## 🎯 核心改善目標

### 1. ChromaDB 資料分離管理 (高優先級)
**現況問題**: 所有教材資料混合存放在同一個向量資料庫中，無法區分來源
**改善目標**: 實現多資料庫架構，每個教材檔案獨立存放

#### 具體要求:
```python
# 類似架構
vector_db/
├── elementary_english/     # 基礎英文教材
├── vocabulary_1200/        # 1200基礎單字
├── grammar_basics/         # 文法基礎
├── conversation/           # 對話練習
└── custom_materials/       # 自訂教材
```

#### 實作規格:
- 每個教材使用獨立的 ChromaDB collection
- 支援動態新增/刪除教材資料庫
- 提供資料庫列表和狀態查詢功能
- 實現資料庫版本控制和更新機制

### 2. 問答系統檔案選擇功能 (最重要)
**現況問題**: 系統只能查詢所有資料，無法指定特定教材
**改善目標**: 用戶可以選擇查詢特定教材或組合多個教材

#### 具體要求:
```python
# 使用範例
qa_system = QASystem()
qa_system.select_databases(["elementary_english", "vocabulary_1200"])
response = qa_system.query("What is simple present tense?")

# 或者互動式選擇
qa_system.interactive_mode()
# > 可用資料庫: [1] 基礎英文 [2] 1200單字 [3] 文法基礎
# > 請選擇 (可多選，用逗號分隔): 1,3
```

#### 實作規格:
- 提供資料庫選擇介面 (命令列 + 程式化)
- 支援單一或多個資料庫組合查詢
- 顯示每個資料庫的基本資訊 (檔案數量、更新時間等)
- 查詢結果標示來源資料庫

### 3. API Manager 整合 (中優先級)
**現況問題**: 直接使用單一 Gemini API Key，缺乏負載平衡和錯誤處理
**改善目標**: 整合現有的 `api_manager.py` 多 API 管理系統

#### 具體要求:
在 `api_manager.py` 中新增 LangChain 相容的類別:
```python
class SafeGeminiLLM(LLM):
    """使用 API Manager 的安全 Gemini LLM"""
    
    def __init__(self):
        self.api_manager = SafeGenerativeModel()
    
    def _call(self, prompt: str, **kwargs) -> str:
        return self.api_manager.generate_content(prompt)
    
    @property
    def _llm_type(self) -> str:
        return "safe-gemini-llm"
```

#### 實作規格:
- 繼承現有 API Manager 的所有功能 (多 Key 輪替、錯誤處理、統計)
- 提供 LangChain 相容介面
- 保持與現有系統的一致性
- 支援 API 使用統計和監控
